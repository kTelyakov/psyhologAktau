## 2. Техническое SEO — чеклист до запуска

- [ ] **Google Search Console** — подтвердить домен, отправить `sitemap.xml`
- [ ] **Яндекс.Вебмастер** — то же самое. В Казахстане Яндекс даёт
      заметную долю, игнорировать нельзя
- [ ] **Проверить переезд**: выгрузить все URL из старого sitemap,
      прогнать по новому сайту, убедиться что нет 404 и 500
- [ ] **Карта старых URL → новых**: сейчас совпадение побайтовое,
      но после запуска надо убедиться по факту, а не по плану
- [ ] `canonical` на каждой странице — проверить, что не дублируются
- [ ] Страницы пагинации блога (когда появятся) — `rel=prev/next`
      или `noindex` на вторую и далее
- [ ] Проверить, что `/blog/stati-gulsary-karajchikovoj/` с одной статьёй
      не создаёт тонкую страницу — либо наполнить, либо схлопнуть
- [ ] 404-страница отдаёт именно 404, а не 200 (проверено, но перепроверить на проде)
- [ ] HTTPS, HSTS, редирект `www` → без `www` (или наоборот — выбрать одно)
- [ ] `hreflang` — после появления казахской и английской версий (§7)

## 4. Контентное SEO

### Семантическое ядро — собрать до наполнения

| Кластер | Примеры | Посадочная |

- [ ] Проверить, какие из 58 статей уже ранжируются — через GSC
      после подключения. Не трогать то, что работает
- [ ] Под каждый кластер — одна посадочная, без каннибализации

### Работа со статьями

- [ ] **Проверить title и description у всех 58**: сейчас они
      генерируются из `title` и `excerpt`. Для топовых по трафику
      переписать руками — поля `meta_title` и `meta_description`

- [ ] **Перелинковка**: сейчас только «ещё в рубрике». Добавить
      ссылки из статей на страницы услуг — это путь от информационного

- [ ] **Обновить даты**: все статьи 2018–2019 годов. Актуализировать
      лучшие и проставить `dateModified` — свежесть влияет на выдачу

Казахская и английская версии (архитектура — в `I18N_PLAN.md`).

- [ ] `hreflang` между языковыми версиями + `x-default`

      доля казахоязычных запросов высокая, а конкуренция в них ниже

## 8. Мониторинг

### Что ставить

| Инструмент | Зачем | Приоритет |
|---|---|---|
| **Google Search Console** | позиции, показы, клики, ошибки индексации | обязательно |
| **Яндекс.Вебмастер** | то же для Яндекса | обязательно |
| **Google Analytics 4** или **Plausible** | поведение, конверсии | обязательно |
| **Uptime-монитор** (UptimeRobot, Healthchecks) | сайт лежит — трафик уходит | обязательно |
| **Sentry** | ошибки фронта и API | желательно |
| **CrUX / web-vitals** | полевые Core Web Vitals | желательно |

Plausible против GA4: GA4 бесплатен и даёт больше, Plausible проще
и не требует баннера про cookie. Для сайта такого размера Plausible
удобнее, но решать тебе.

### Что мерить именно здесь

Главная метрика — **не трафик, а заявки**. Сайт существует ради звонков
и форм, а не ради показов.

- [ ] Цель в аналитике: отправка формы (`POST /api/v1/leads` → успех)
- [ ] Цель: клик по телефону (`tel:` ссылки)
- [ ] Цель: клик по WhatsApp/Telegram, когда появятся
- [ ] Отчёт: из какой статьи пришла заявка — поле `source_page`
      в таблице `leads` это уже пишет, нужен только разрез
- [ ] Отслеживать долю заявок с мобильных — скорее всего большинство

### Технический мониторинг

- [ ] `/api/v1/health` в uptime-монитор, интервал 5 минут
- [ ] Алерт на 5xx в nginx-логах
- [ ] Алерт на падение `psyholog-api` / `psyholog-web` (systemd + OnFailure)
- [ ] Проверка, что `pg_dump` по cron реально создаёт файлы,
      а не падает молча
- [ ] Место на диске — ISR-кэш и логи растут незаметно

### Регулярные проверки

| Что | Как часто |
|---|---|
| GSC: ошибки индексации, упавшие страницы | раз в неделю |
| Позиции по ядру | раз в две недели |
| Заявки: количество и источники | раз в неделю |
| Lighthouse на проде | раз в месяц и после каждого релиза |
| Битые ссылки (Screaming Frog / linkinator) | раз в квартал |
| Актуальность контента, обновление дат | раз в квартал |

## 9. Риски при переезде

1. **Падение трафика в первые 2–4 недели** — нормально при смене
   платформы, если URL сохранены. Если через месяц не восстановилось —
   искать проблему, а не ждать
2. **Потеря позиций из-за изменения контента**: тексты статей
   переработаны конвейером (абзацы, вычищен мусор). Содержание
   не менялось, но Google переиндексирует — возможны колебания
3. **Смена автора у 11 статей**: атрибуция сменилась на Карайчикову.
   Для E-E-A-T это скорее плюс — один эксперт вместо двух
4. **Расформированная рубрика**: 308-й редирект стоит, но проверить
   в GSC, что старый URL склеился с новым
5. **Attachment-страницы**: 3 мусорных URL закрыты редиректом.
   Если они были в индексе — проследить за выпадением

2. Выгрузить текущие позиции и список индексированных URL — точка отсчёта

5. Запросить переобход ключевых страниц
6. Поставить uptime-монитор

**Первый месяц**
7. Ежедневно смотреть ошибки индексации в GSC
8. Отследить склейку старых URL
9. Замерить Core Web Vitals на проде
